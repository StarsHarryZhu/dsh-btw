# dsh-btw · 旁问

DeepSeek Harness（网页版）插件：在当前会话里顺手问一句，不打断主任务。

插件名 `dsh-btw`，版本 v0.1.0，需要 DeepSeek Harness v0.2.1-rc.1 或更高版本。

- 输入 `/btw 问题`，或在回复里选中文字后点「旁问」。
- 默认用 `deepseek-flash`（推理强度 low）回答；唯一能用的工具是联网搜索。
- 回答显示在对话流里的卡片上。回答期间只转圈，不显示思考过程。卡片标题由模型和回答一起生成，折叠后只留标题。
- 划词旁问的卡片插在被划词的那条回复下面。
- 卡片可以复制、折叠、删除；删除写进会话记录，刷新后也不会回来。正在回答时删除会中止。
- 右侧边栏的「旁问历史」页列出当前会话的全部旁问（不含已删除的），可以一键定位。
- 插件页里可以改回答模型、推理强度和最多搜索轮数，也可以选「与会话一致」。

## 为什么不会再乱调工具

旧插件把主会话整段 fork 给子代理：历史里全是 `tool_use` / `tool_result`，请求里却没有任何工具定义。这种请求不在模型的训练分布里，所以 flash 会继续尝试调工具。

Claude Code 的 `/btw` 做法是：fork 时保持和主会话完全一样的 system、工具定义和前缀，所以请求本身是自洽的；再用一段 system-reminder 声明"你没有工具、只回答一次"；所有工具调用都在权限层拒绝；只跑一轮；如果模型只调了工具没给文字，就显示一句兜底说明。

本插件换了模型，主会话的缓存本来就用不上，而且要支持联网搜索，所以没有照搬"保持工具定义"这一条，改成：

1. 主会话历史**展平成纯文本**再交给模型。工具调用写成"助手调用了 read_file：…"这样的叙述，请求里没有任何原生工具结构。
2. 只声明 `web_search` 一个工具。调用其他工具一律返回"只能用 web_search"的错误结果；某一步如果只调了被拒绝的工具，就直接进入收尾。
3. 最多搜索 `maxSteps` 轮（默认 4）。收尾请求不带任何工具，搜索结果以文本形式附上。
4. Claude Code 的提醒语、拒绝、兜底说明都照搬了。

## 安装（本地开发）

```bash
node scripts/link-dev.mjs
npm test
```

然后在 `~/.dsh/profiles/web/package.json` 的 `dependencies` 里加 `"dsh-btw": "link:<本目录的绝对路径>"`，把 `dsh-btw` 加进 `dsh.profile.bundles`，并移除 `@michengai/dsh-btw`（两个插件都注册 `/btw`）。安装依赖后，在桌面端「重新加载」。

## 开发

- `node build.js`：类型检查、生成 `lib/`、打包浏览器端，并做自检。
- `npm test`：先构建，再跑全部测试。
- 结构和约束见 `AGENTS.md`。
